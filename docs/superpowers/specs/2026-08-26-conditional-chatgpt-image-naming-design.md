# AI Image Canvas 条件式 ChatGPT 图片命名设计

## 目标

当 ChatGPT 生图回复没有返回图片名称时，AI Image Canvas 自动在当前 Chat 会话发送一次简短命名请求，并将返回名称用于新图片。不得再次生图，不调用 OpenAI API，不读取或导出登录凭据。

## 当前问题

主生图 Prompt 已要求 ChatGPT 使用 `图片名称：名称` 格式返回名称，但图片工作流经常只返回图片。适配器因此拿不到 `suggestedName`，后端只能从原 Prompt 生成名称。包含 `@1`、操作命令或长句的 Prompt 会产生 `1` 等无意义名称。

## 方案

采用条件式二阶段命名：

1. 保留主生图请求中的同轮命名要求。
2. 检测到最终图片后立即收集图片字节，避免后续页面变化导致结果丢失。
3. 若主回复已包含有效名称，直接使用，不发送额外消息。
4. 若名称缺失，在同一 Chat 会话发送一次纯文本请求：只为刚生成的图片拟定 2–12 个字符的简短中文名称，并严格回复 `图片名称：名称`，不得生成或修改图片。
5. 轮询新 Assistant 回复并提取名称，最长等待 30 秒。
6. 命名请求失败、超时、拒绝或页面结构变化时，不阻塞图片导入，改用本地语义兜底名称。

## 组件边界

### ChatGPT 名称适配器

新增独立的名称回复检测模块，负责：

- 以提交命名请求前的 Assistant 消息 ID 为边界；
- 只读取边界之后最新 Assistant 回复；
- 区分等待中、已命名与不可恢复的页面状态；
- 仅提取 `图片名称：...` 后的单行文本。

它不负责提交 Prompt、下载图片或写数据库。

### 生成编排器

生成编排器在图片字节收集成功后解析名称：

- 优先使用主回复的 `suggestedName`；
- 缺失时调用可注入的 `requestSuggestedName`；
- 命名阶段沿用 `collecting` 状态，并显示“图片已生成，正在请 ChatGPT 命名”；
- 命名失败仅记录为兜底路径，不把整个生成任务标记失败；
- 最终将可选建议名称传给现有批量导入接口。

### 后端本地兜底

改进 Prompt 命名规则：

- 移除 `@数字`、`@名称` 引用标记；
- 移除“生成、移除背景、保持主体、设为透明”等操作性模板语句；
- 结果为空、只有数字或过短时使用 `未命名图片`；
- 继续使用现有唯一名称分配，重复名称追加 `(2)`、`(3)`。

## 错误处理

- ChatGPT 已返回名称：不发送第二条消息。
- 命名请求提交失败：继续导入，使用本地兜底。
- 命名回复超过 30 秒：继续导入，使用本地兜底。
- 用户取消生成任务：立即终止命名轮询，不继续导入。
- 返回名称包含 `@`、引号或标签：沿用后端名称清洗。

## 测试

- 适配器：能从边界后的最新 Assistant 回复提取名称；忽略旧回复和用户文本；无格式名称保持等待或超时。
- 编排器：主回复有名称时不发命名请求；缺失时只发一次；命名失败仍导入。
- 后端：`@1 移除此图像的背景...` 不再命名为 `1`；数字、空白和模板指令回退到 `未命名图片`。
- 回归：现有生图、引用图、透明背景、下载和画布导入测试继续通过。

## 非目标

- 不实现本地视觉模型或图像内容识别。
- 不调用 OpenAI API。
- 不修改 ChatGPT 登录机制。
- 不在本阶段实施左侧栏、快速创作、图库与 Canvas 解耦重构；该工作按用户附带规格作为独立阶段处理。
