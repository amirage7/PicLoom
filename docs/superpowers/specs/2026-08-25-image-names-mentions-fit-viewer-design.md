# 图片命名、@ 多图引用与适应窗口设计

日期：2026-08-25  
状态：已获用户确认，待实现

## 目标

让画布中的每张图片具有可编辑且可被引用的名称；移除 ChatGPT 面板中独立的参考图下拉框，改为在 Prompt 中通过自然语法 `@图片名` 选择一张或多张参考图；原图查看器每次打开时完整显示图片。

示例：

`将@假面骑士build的身体和@喜羊羊的头部合成一个新的角色`

上述 Prompt 会按出现顺序上传“假面骑士build”和“喜羊羊”两张图片，并向 ChatGPT 补充附件顺序说明。

## 已确认的产品规则

1. 同一项目内图片名称唯一。
2. 图片名称可在右侧图片详情中编辑，画布节点直接显示该名称。
3. Prompt 使用不带括号的自然 `@图片名` 语法。
4. 一个 Prompt 可以引用多张图片；重复提及同一图片只上传一次。
5. 第一张被引用图片是生成结果的主父图；其余图片是辅助参考，不创建额外父子边。
6. 原图查看器每次打开都重置为“适应窗口”。

## 交互设计

### 图片节点与重命名

- 节点图片下方第一行显示名称，第二行可保留截断后的 Prompt 摘要，底部显示创建时间。
- 右侧图片详情在 Prompt 之前增加“图片名称”输入框。
- 输入框失焦或按 Enter 时保存；Escape 恢复原值。
- 名称会去除首尾空白，不允许为空，不允许超过 80 个字符。
- 名称冲突时不保存，保留编辑内容并显示“当前项目已有同名图片”。
- 名称比较使用 Unicode NFKC 规范化和大小写折叠，因此 `Build` 与 `build` 视为同名。

### Prompt 中的 @ 选择

- 删除 ChatGPT 面板顶部的“参考图片（可选）”下拉框及单图预览卡。
- 用户在 Prompt 中输入 `@` 后，在输入框附近显示当前项目的图片候选列表。
- 每项显示缩略图和图片名称；继续输入会按名称筛选。
- 支持鼠标选择，以及方向键、Enter/Tab 和 Escape。
- 选择后插入 `@完整图片名`，光标移动到名称之后。
- Prompt 下方显示简洁状态，例如“将引用 2 张图片”，并展示已解析出的名称；这不是另一个选择器。
- 提交前重新解析文本。无法解析的 `@` 引用会阻止提交并指出失效名称，避免静默漏传图片。

### 原图查看器

- 查看器打开时处于 `fit` 模式，图片以 `max-width: 100%`、`max-height: 100%` 和 `object-fit: contain` 完整显示。
- 工具栏显示“适应”，并保留放大、缩小、恢复适应和保存原图。
- 从适应模式首次放大时，以当前适应尺寸为基准放大；关闭后再次打开重新回到适应模式。
- 查看器不再默认使用图片原始像素的 100% 宽度。

## 数据设计与迁移

### Images 表

增加：

- `name`：用户可见名称，最长 80 字符。
- `name_key`：由 `NFKC(name).casefold()` 得到，仅用于同项目唯一性。
- 唯一索引：`(project_id, name_key)`。

迁移旧数据时按创建时间顺序生成名称：

1. 优先使用清理后的 Prompt；去除常见的“生成一张”“生成”等请求前缀并截断到 80 字符。
2. Prompt 为空时使用文件名（不含扩展名）。
3. 仍为空时使用“未命名图片”。
4. 冲突时依次追加 ` (2)`、` (3)`，确保迁移可重复且不会失败。

新上传图片默认使用文件名；新生成图片默认使用清理后的 Prompt；复制图片默认使用“原名称 副本”，冲突时自动编号。所有名称之后均可编辑。

### API

- 图片响应增加 `name`。
- 图片更新接口接受 `name`，在服务层完成规范化与项目内唯一校验。
- 重名返回 HTTP 409 和稳定错误码，前端显示中文错误。
- 图片的 Prompt、标签、位置和父子关系接口保持兼容。

## @ 解析规则

- 候选来源仅限当前项目图片。
- 提交解析按名称长度从长到短匹配 `@完整名称`，避免短名称吞掉长名称前缀。
- 匹配结果按 Prompt 中首次出现的位置排序，再按图片 ID 去重。
- 名称后的中文、标点和空格不属于名称；候选选择时已知完整名称，因此正常输入路径不会产生歧义。
- 用户手工输入了无法与当前图片名称匹配的 `@...` 时，提交被阻止并要求重新选择。
- 图片改名后，旧 Prompt 中的旧名称不会偷偷映射到其他图片。

解析逻辑放入独立纯函数模块，供输入建议、提交校验和测试共同使用。

## 生图数据流

1. 前端解析 Prompt，得到按出现顺序排列的 `referenceImages: [{ imageId, name }]`。
2. 前端创建本地生成任务，`parent_image_id` 使用第一张引用图 ID；无引用时为 `null`。
3. Electron 请求协议同时携带原 Prompt、主父图 ID 和完整引用图片数组。
4. Electron 从本地后端读取所有引用图片，写入同一临时目录，并通过一次文件选择上传全部附件。
5. Electron 在原 Prompt 前添加附件映射，例如：

   `参考图片顺序：第1张“假面骑士build”；第2张“喜羊羊”。请严格按照用户文本中的 @名称 对应这些附件。`

6. ChatGPT 页面收到多附件后再提交 Prompt。
7. 收集生成图片并保存到当前项目，生成结果的 `parent_id` 仍为第一张引用图。
8. 无论成功、失败或取消，都清理全部临时参考文件。

这不会调用 OpenAI API，也不会使用 Codex 额度；仍使用桌面应用内用户自己登录的普通 ChatGPT 会话。

## 错误与边界情况

- 空名称、过长名称、重名：拒绝保存并在名称输入框附近提示。
- 引用图在提交前被删除或改名：阻止生成，提示重新选择失效的 `@名称`。
- 某张本地图片文件不存在：整个生成任务失败，不提交残缺的附件集合。
- 多附件上传失败：清理临时文件并保留 Prompt，允许重试。
- 没有 `@` 引用：行为与普通文字生图一致。
- 只出现单独的 `@`：显示候选但不视为有效引用。

## 测试与验收

### 后端

- 数据库迁移为旧图片生成唯一名称。
- 新增、上传、复制、生成和更新图片时名称正确。
- 同项目重名返回 409；不同项目可使用同名。

### 前端

- 节点显示名称而非把 Prompt 当标题。
- 详情面板可重命名并显示重名错误。
- 输入 `@` 展示候选，筛选和键盘选择可用。
- 多个引用按文本顺序解析、去重并进入桌面请求。
- 已删除或改名的引用阻止提交。
- 原图查看器每次打开都处于适应模式，放大后关闭再打开仍恢复适应。

### Electron

- IPC 校验完整引用数组并限制数量和字段长度。
- 所有引用图片在提交 Prompt 前一次性附加。
- 附件映射文字顺序与实际上传顺序一致。
- 成功、失败和取消路径均清理所有临时文件。

### 手工验收

1. 将两张图分别命名为“假面骑士build”和“喜羊羊”。
2. 输入示例 Prompt，通过 `@` 候选选择两张图。
3. 确认 ChatGPT 收到两张附件并生成组合角色。
4. 确认生成结果自动进入画布，并与第一张引用图形成父子连线。
5. 打开任意横图、竖图和超大图，确认首次均完整可见且可以保存原图。

## 非目标

- 不在 textarea 内实现富文本高亮或可删除的 Mention 芯片。
- 不支持跨项目引用图片。
- 不改变数据库的一对一主父图关系为多父图关系。
- 不实现 OpenAI API、模型训练或新的图片生成模型。
