# 透明背景生图与 ChatGPT 自动命名设计

日期：2026-08-26  
适用版本：AI Image Canvas 0.2.x

## 目标

1. 在 ChatGPT 生图 Prompt 区提供“透明背景”开关，让用户无需引用已有图片，也能直接要求生成透明背景的新图片。
2. 保留图片详情中的“移除背景”按钮，用于处理已经存在的图片；两个入口语义互不混淆。
3. 生成图片的自动名称不包含 `@`，并优先采用 ChatGPT 在同一次回复中给出的简短名称。
4. 自动命名不额外发送第二条 ChatGPT 消息，不增加一次独立对话调用。

## 交互设计

- Prompt 输入框下方增加一个可切换的“透明背景”按钮，默认关闭。
- 开启时显示明确的激活状态和辅助说明；再次点击即可关闭。
- 开关可用于无参考图的普通生图，也可与一个或多个 `@图片名称` 引用共同使用。
- 用户可继续在 Prompt 中自行描述透明背景；开关开启后，应用仍追加统一约束，提升透明输出的稳定性。
- 图片详情中的“移除背景”入口保持原位置和原行为。

## Prompt 组装

界面保存用户原始 Prompt 和透明背景布尔值。桌面生成编排器在真正提交 ChatGPT 前组装指令：

1. 保留现有参考图顺序说明。
2. 透明背景开启时追加：`将最终图片背景设为透明，保持所有前景主体完整无损，边缘干净平滑。不要添加纯色、白色或棋盘格背景。`
3. 追加命名要求：为最终图片给出 2–12 个字符的简短中文名称，并使用固定格式 `图片名称：名称`。

命名要求与生图请求在同一条消息中发送，不另起一次 ChatGPT 请求。

## 名称提取与兜底

- ChatGPT 页面适配器只从本次最新 Assistant 回复中提取 `图片名称：...`。
- 提取结果进入最终图片批次导入接口，后端负责统一清洗和唯一性分配。
- 清洗规则：移除 `@`、首尾空白、成对引号、换行和固定标签；最多保留 80 个字符。
- 若 ChatGPT 没有给出有效名称，后端从用户原始 Prompt 生成兜底名称：先移除 `@图片名称` 引用和常见“生成一张”前缀，再截取可读描述；仍为空时使用文件名。
- 同一项目出现重名时继续使用现有 `(2)`、`(3)` 后缀机制。

## 数据与接口

- `DesktopGenerationRequest` 增加 `transparentBackground: boolean`。
- ChatGPT 完成态增加可选 `suggestedName`。
- 桌面批次上传增加可选 `suggested_name` 表单字段。
- 数据库不新增字段；最终名称继续写入现有 `images.name`。
- Generation task 保留用户原始 Prompt，避免把内部透明背景与命名协议显示到图片详情中。

## 错误处理

- 名称缺失或格式变化不会阻断图片导入，直接使用本地兜底名称。
- 名称不合法时后端清洗；清洗后为空则继续兜底。
- 透明背景属于生成约束，ChatGPT 未产生真实透明通道时仍导入结果，不把正常生成误判为失败。

## 测试范围

- 前端：透明背景开关默认关闭、可切换，并随生成请求传递。
- 桌面端：Prompt 组装仅在开关开启时追加透明约束；始终追加同请求命名要求。
- 适配器：从最新 Assistant 回复提取名称，不读取旧回复或用户消息。
- 后端：优先使用建议名称，清除 `@`；名称缺失时从 Prompt 生成无 `@` 兜底；重名后缀保持有效。
- 回归：普通生图、`@` 多图引用、图片详情移除背景、最终图片单张导入和多来源连线保持原行为。
